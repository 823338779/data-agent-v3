### Memory Organization

1. 核对用户指定范围内的条目。首次读取使用 `memory`，只传 `{"action":"read"}`。本轮已有成功读取且快照仍是最新时，直接使用。
2. 依照 Storage Classify 找出错放条目；本轮尚无分类步骤时调用 `load_skill`，传入 `{"skill_name":"storage-classify"}`。比较偏好时先核对作用范围，再核对值。相同范围且意思相同才建议合并；相同范围但值互斥才列为冲突。例如“日报用元”和“周报用万元”可以同时成立。
3. 用用户的明确更正或条目中的有效期判断是否失效。行的排列顺序不能证明新旧。若同一默认值有两个互斥选项且依据不足，标为“待确认”，只引用冲突的两条原文并询问哪条适用。此时没有可建议的合并文本。
4. 对每个问题给出**相关条目原文、判断依据、建议动作**。仅在改法有依据时给出完整新文本；涉及凭据时只指出其位置并遮蔽值。没有问题时，直接说明核对结果。

给出建议后结束本轮，不执行修改或遗忘。后续只处理用户明确指定的条目和动作；笼统认可清单不代表逐条授权。
